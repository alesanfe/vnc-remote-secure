# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| latest main | Yes |
| tagged releases | Yes |
| older branches | No |

## Reporting a Vulnerability

If you discover a security vulnerability, please report it responsibly:

1. **Do NOT open a public GitHub issue.**
2. Email the maintainer privately (see repository owner profile).
3. Include:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

You will receive a response within 72 hours. Vulnerabilities will be
acknowledged in `CHANGELOG.md` after a fix is released.

## Security Features

### Authentication

- **VNC password** — Required, hashed (UltraVNC/TigerVNC format)
- **Web terminal** — Basic auth, username/password from `.env`
- **User UI** — Session-based with CSRF protection
- **Rate limiting** — Login attempts limited per IP (5 attempts / 5 min window)

### Transport Security

- **SSL/TLS** — Self-signed certificates generated by default (Linux)
- **Let's Encrypt** — Optional, requires `DUCK_DOMAIN` and `EMAIL`
- **noVNC** — `--ssl-only` flag when SSL is enabled
- **Web terminal** — SSL when certificates are available

### Credential Handling

- **No hardcoded credentials** — All secrets from `.env` or generated at runtime
- **No credential logging** — Passwords redacted in console output
- **No credential args** — Secrets passed via environment, not command-line args
- **Generated passwords** — Strong random generation (openssl → /dev/urandom → python3)
- **`.env` gitignored** — Never committed to repository

### Session Security

- **Cookies** — `HttpOnly`, `SameSite=Lax`, `Secure` (when HTTPS)
- **CSRF** — Token validation on state-changing requests
- **Constant-time comparison** — `hmac.compare_digest` for password verification

### Network Security

- **Bind addresses** — Health/landing default to `127.0.0.1`
- **Fail2ban** — Optional intrusion prevention (Linux)
- **WebSocket origin** — Validated to prevent cross-site abuse
- **Firewall guidance** — Documented in launcher output

### User Isolation (Linux)

- **Temp user** — Created for session, removed on exit
- **`KEEP_TEMP_USER=false`** — Default (cleanup on exit)
- **`useradd`/`userdel`** — Not `adduser`/`deluser` (more portable)
- **Reserved usernames rejected** — root, www-data, etc.

## Known Limitations

- **VNC password** — Limited to 8 characters (VNC protocol constraint)
- **Self-signed certificates** — Browser shows warning (expected)
- **Windows parity** — No fail2ban, no temp user isolation, no Let's Encrypt
- **Health endpoint** — No authentication (bind to `127.0.0.1` by default)

## Security Headers

The health web server sets:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Cache-Control: no-store`

## Disclosure

This project is provided as-is. Security depends on proper configuration
and network hygiene. See `README.md` for configuration guidance.

## Threat Model

### Assets

| Asset | Description | Impact if compromised |
|-------|-------------|----------------------|
| VNC password | Authentication for desktop access | Full remote desktop control |
| Terminal credentials | Authentication for web terminal | Remote code execution |
| SSL private keys | TLS certificate keys | Man-in-the-middle, decryption |
| DuckDNS token | Dynamic DNS API token | DNS hijacking, domain takeover |
| User session | Authenticated browser session | Unauthorized access to services |
| Temp user account | Linux isolation user | Privilege escalation if misconfigured |
| Configuration (.env) | All credentials and settings | Full system compromise |

### Threats

| Threat | Likelihood | Impact | Controls |
|--------|-----------|--------|----------|
| **Brute force** (VNC/terminal password) | Medium | High | Rate limiting, Fail2ban, strong password validation |
| **Session hijacking** | Low | High | HttpOnly cookies, SameSite, Secure flag, CSRF tokens |
| **Cross-Site WebSocket Hijacking** | Low | High | Origin header validation on all WebSocket servers |
| **Port exposure** (internal services) | Medium | High | Services bind to localhost, nginx as sole entry point |
| **Secret leakage in logs** | Medium | Critical | Passwords redacted, no secret logging, Gitleaks in CI |
| **Secret leakage in process list** | Low | High | Credentials from files, not command-line args |
| **DNS hijacking** (DuckDNS token theft) | Low | High | Token in .env (gitignored), Gitleaks scanning |
| **Privilege escalation** | Low | Critical | Temp user, systemd NoNewPrivileges, ProtectSystem |
| **TLS misconfiguration** | Medium | Medium | Self-signed certs with 600 perms, Let's Encrypt for production |
| **Information disclosure** (health endpoint) | Low | Low | Minimal public response, detailed info behind auth |
| **Injection attacks** (Flask UI) | Low | High | Input validation, parameterized queries, error sanitization |
| **Supply chain** (dependency vulnerabilities) | Low | Medium | Trivy scanning, pinned versions in requirements.txt |

### Controls by Layer

**Network layer:**
- nginx as sole public entry point (port 443)
- Internal services bound to 127.0.0.1
- Fail2ban for repeat offenders (Linux)
- Firewall guidance documented

**Application layer:**
- Rate limiting on login (5 attempts / 5 min)
- CSRF protection on state-changing requests
- WebSocket origin validation
- Input validation and sanitization
- Generic error messages (no exception leakage)

**Authentication layer:**
- Strong password requirements (uppercase, lowercase, digit, 8+ chars)
- Weak password rejection (changeme, admin123, etc.)
- Constant-time password comparison (`hmac.compare_digest`)
- Session-based auth with secure cookies

**System layer:**
- Temporary user with minimal privileges (Linux)
- systemd hardening (NoNewPrivileges, ProtectSystem, PrivateTmp)
- Secret files with 600 permissions
- `doctor` command validates permissions and configuration

**CI/CD layer:**
- Gitleaks scans for secrets in every PR
- Trivy scans containers and filesystem
- ShellCheck catches common Bash vulnerabilities
- Pre-commit hooks prevent committing .env or secrets

### Recommended Additional Controls (Not Implemented)

These are recommended but not implemented in the current version:

- **VPN access** (WireGuard/Tailscale): Preferable to exposing services publicly
- **MFA/2FA**: Second factor for terminal and UI access
- **Audit logging**: Structured JSON logs with session IDs and timestamps
- **Session expiration**: TTL-based session revocation
- **Certificate pinning**: For self-signed certificate deployments
- **CSP headers**: Content-Security-Policy for web components
